# M5 / M6 使用与实现说明

## AI 辅助

首页 → AI 辅助，或设置 → AI 辅助记账与月报。普通手动记账始终可离线使用。

在“AI 服务配置”填写服务名称、HTTPS Base URL 和模型。Base URL 后追加 `/chat/completions`，例如服务要求 `/v1/chat/completions` 时填写 `https://服务地址/v1`。支持 Chat Completions 文本与多模态图片协议，超时 5–120 秒、输出 128–8192 tokens；默认不自动重试，可对 HTTP 429 和 5xx 设置最多两次重试。

默认使用 `max_completion_tokens` 和 JSON 模式；旧兼容服务可选择 `max_tokens` 或关闭 JSON 模式。无论服务是否支持 JSON 模式，客户端都会严格解析草稿。格式参考 [OpenAI 官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)；JSON 模式不保证业务字段正确，客户端校验和人工确认不可省略。不同厂商和模型的参数支持仍需实际连接验证。

- 密钥保存在 Keychain，使用 `WhenUnlockedThisDeviceOnly`；UserDefaults 只存服务配置。密钥不进入账本、CSV 或普通备份。服务名称、地址或模型变化时不会沿用旧密钥，旧配置的密钥会清理。
- 测试连接只发送固定测试文本，点击确认后执行。不会附带账本、分类或账户。
- 每次草稿请求前展示服务名称、地址、模型及发送范围，需确认本次发送。发送当前原文、当前日期、可用分类/账户的名称与 ID；不发送已有流水。
- **账单截图识别**：在“一句话记账”下方可选择微信、支付宝等支付账单截图。Mac 点击“选择本地账单图片”打开系统文件选择器，从本地文件系统选择图片；iOS 保留相册选择。由所配置的多模态 LLM 直接解析图片并生成一笔人民币收入/支出草稿，不经过单独的 OCR 服务。截图先在本机压缩：最长边 1280px、JPEG 重新编码（自动降质至 3 MiB 以内），原图 EXIF/GPS 等元数据随之丢弃，应用不另存原图。选择的图片文件最大 32 MiB；Mac 在用户授权的文件访问范围内限量读取。
- 截图请求使用 OpenAI 兼容多模态消息（`image_url` data URL）；带图请求体上限 12 MiB，纯文本仍为 128 KiB。服务不支持图片输入时会返回错误，此时可改用文字描述或手动记账。
- 发送截图前同样确认目标服务与范围，并展示压缩后的尺寸与大小；截图中的商户、金额、时间等信息会上传给该服务。提示词明确以图片为准、文字只补充缺失信息，金额取实际支付/到账金额；支付界面不自动对应账户，没有交易时间不猜今天。多笔、非账单、未完成交易、非人民币、转账或退款要求返回空字段，模糊字段不猜测。图片草稿保留模型返回的有效分类，不用文字的本地分类规则覆盖。更换或移除图片会清除旧草稿；保存前必须人工核实。
- 月报请求仅发送当前选定月份的本机确定性收支及分类汇总，不发送逐笔流水、账户、备注。原数值和发送快照始终可查看；账本改变后旧说明失效。
- 网络请求使用无缓存、无 Cookie 的临时会话，拒绝重定向。服务错误只显示状态说明，不显示响应体或密钥。响应最多 256 KiB；超时、断网、限流、截断、拒绝或无效 JSON 保留原文，可取消或转手动填写。
- 模型只产生候选草稿，不自动入账。首版提取一笔人民币收入/支出；转账、退款和多笔描述需手动处理。缺失/无效金额、日期、分类或账户给出明确提示；缺少日期时编辑器暂显示今天，必须核实。保存前需勾选字段核实，随后仍通过普通仓储金额、日期和引用校验。
- 分类先提供本地名称/常见餐饮词建议。AI 输出不具有命令、工具调用、链接跳转或写库能力；额外 JSON 字段被拒绝。
- 调用可能产生供应商费用。真实服务与密钥未随项目预置，本轮验证使用 URLProtocol 模拟网络与独立测试账本，不产生真实供应商调用。截图压缩（尺寸、元数据去除、大小上限）与多模态请求协议由单元测试覆盖。

草稿 JSON 的字段均为字符串或 null：

```json
{"kind":"expense","amount":"35.00","day":null,"categoryID":"expense.daily.2","accountID":null,"note":"午饭"}
```

## CSV 导出

设置 → CSV 导出，先选择数据类型、期间、是否包含停用/历史版本、UTF-8 BOM，再预览并选择系统文件导出位置。取消不改变账本。

四种类型分别导出：每日流水、历史期间汇总、月度调整、对账比较。

- 使用整数分生成精确小数文本，保留稳定 ID、引用、币种、日期/期间、原始精度及记录类型。
- 历史汇总与调整按与所选期间相交的原区间导出，跨范围时明确标注，不能把完整历史合计当作选定月金额。
- 对账比较包含依据版本、已提供/缺失状态及导出时的整月账本和差额，**不属于新增收支**。过去核对时的快照在完整备份的审计中保留。
- UTF-8、可选 BOM、CRLF 行尾，双引号/逗号/换行正确转义。文本字段以 `= + - @`（含全角和前置空白/控制符）开头时添加单引号，阻止表格公式执行；程序生成的有符号金额仍为正常数字。
- 预览最多显示 20 条，导出文件包含选定范围全部匹配记录。CSV 为明文，不包含 AI 密钥或服务配置。可选择“我的 iPhone → Lot Bill”本机目录，或用户自选的其他文件位置。

## 完整备份与恢复

设置 → 备份与恢复。逻辑 JSON 备份独立于 SwiftData Schema（普通账本版本 1，含历史退款审计时版本 2；当前程序兼容两者），包含以下九类完整记录：

账户、分类、流水、历史期间汇总、导入批次、月度依据、对账项目、月度调整全部修订、导入/核对审计。

保留所有稳定 ID、整数分金额、日期、期间精度、有效状态、版本与引用。文件的 `createdAt` 和记录时间采用 Foundation Codable 的日期表示（距 2001-01-01 UTC 的秒数）；不用来替代流水的自然日期。原导入文件未复制保留，因此备份包含必要来源快照，不含原始 XLSX/CSV 附件。

AI 服务配置、Keychain 密钥、发送授权、常用模板、最近选择及本机备份提醒状态不进入备份。恢复后保留设备当前 AI 配置，每次发送仍需确认。

### 恢复流程

1. 读取 JSON（最多 40 MiB，合计最多 100,000 条记录），验证格式与版本。
2. 校验重复 ID、基础分类、金额、币种、日期、账户/分类层级、退款/转账关系、历史覆盖冲突、对账版本/项目、调整修订及来源审计。未知较新版本、损坏格式或断裂引用直接拒绝。
3. 展示备份时间、来源和各类型条数，明确整体替换而非合并。确认前如账本已变化，要求重新预览。
4. **首次数据库变更前**将当前完整账本原子保存为本机恢复点。恢复点写入失败时不触碰账本。
5. 在单一 SwiftData 保存事务内按稳定 ID 更新/插入并删除备份中不存在的记录，避免相同 ID 的删除/插入冲突。失败回滚，原账本和恢复点保留；进程中断的数据库原子性由持久化事务保证。
6. 成功后刷新所有统计并返回首页，重建导航，避免详情页面继续持有被替换的对象。

恢复点保存在应用私有 `Application Support/RecoveryPoints/<账本作用域>`，由“本机恢复点”入口重新校验、预览和恢复；不会自动上传或自动删除。卸载 App 会丢失本机恢复点，应另行导出完整备份到合适位置。备份 JSON 同样为明文。

## 验证边界

单元测试覆盖真实 Keychain 的合成密钥往返、模拟网络成功/限流重试/超时/断网/取消/重定向、无效和越界 AI 输出、数据最小化、CSV 转义、备份全实体往返、相同 ID 重复恢复、持久化重开、故障回滚、恢复点失败、损坏格式和关联拒绝。

UI 测试使用独立 UUID 测试账本。AI 返回与恢复预览有仅 DEBUG 且仅测试作用域启用的合成注入；不会联网或读取真实财务文件。系统 CSV 导出选择器取消亦在模拟器验证。M7 已补充实际系统文件导出→选回→恢复、万条账本和提交前后进程中断实验，结果见 [M7 验收记录](m7-acceptance.md)。实际文件场景仍使用合成账本；真实供应商、用户真实账单、最低 iOS 18 和物理断电未覆盖。

备份成功状态、记录差异、应用内提醒与隔离恢复演练见 [P1/P2 更新说明](p1-p2.md)。
