## 1. 实施顺序

先完成本机 iOS 开发环境和最小工程验证，再实现每日维护、历史初始化、月底对账、AI 和数据导出。各阶段使用合成数据开发，真实账单仅在用户本机验证。

```text
P0 本机环境 + 样本准备
  → M1 工程与数据规则
  → M2 每日维护与动态统计
  → M3 一次性历史导入
  → M4 月底补充与对账
  → M5 可配置 LLM
  → M6 导出、备份与恢复
  → M7 真机验收与首版交付
```

P0 模拟器与真机环境、工程构建及持久化运行验收已完成。最低系统版本兼容性及真实业务样本保留待办；下列勾选项以实际检查证据为准。

## 4. 重点验证矩阵

测试集中于会影响金额、数据完整性和用户控制的业务规则，不为文档或低风险展示改动添加机械测试。

| 场景 | 预期 |
| --- | --- |
| 金额含小数、千分位、非法字符 | 合法金额精确到分；无法确认的格式进入错误清单 |
| 历史空白、明确零、合计行、无关公式零值 | 分别处理，不自动制造交易或重复总计 |
| 重复文件、改名文件、不同金额的同期间记录 | 重复可拦截，冲突必须显式确认 |
| 历史跨月汇总与部分每日明细重叠 | 不均摊，不静默同时计入 |
| 交易跨月或跨分类修改、删除 | 原和新统计范围都更新，对账状态失效 |
| 月底缺少某分类、范围不一致 | 显示未提供或口径不一致，不当成零 |
| 反复对账、替换对账文件、调整后补入明细 | 不重复追加差额，旧调整可追溯地修订 |
| 导入中断或撤销含已编辑数据的批次 | 无半批脏数据，无无提示删除 |
| LLM 超时、错误 JSON、未知分类、指令型内容 | 保留输入，校验失败不写库，能继续手动记账 |
| CSV 特殊字符与完整恢复 | 显示正常、数值正确、引用完整、密钥不外泄 |

领域规则使用单元测试，持久化、导入和恢复使用集成测试，UI 测试覆盖核心用户路径。阶段验证通过后，仅在新改动、失败或未解决问题涉及其范围时重复执行相应检查。
