# 历史导入与月度对账（M3 / M4）

## 操作入口

- 设置 → 历史文件导入：选取 XLSX / CSV，确认工作表、数据行、大类列、二级分类列、年份及年度金额列，生成预览并确认。
- 设置 → 导入批次与覆盖：原工作表及行号、历史原期间、覆盖提示、撤销影响预览。原文件不复制保存，文件移动不影响已入账金额。
- 统计 / 首页 / 设置 → 月度对账：文件导入或手动填写分类合计，进入分类差异查看流水、补录、编辑或删除；无明细时确认月度调整。
- 流水中的“月度调整”独立成组，不伪装成每日交易。按账户筛选时不显示全部账户调整。

## 文件约定

仅支持用户自整理的分类汇总，不适配第三方平台的逐笔导出。首版为人民币、全部账户。

### 历史汇总

历史文件导入年度支出汇总，保留第一分类和第二分类。2026 年年度数据仅截至 8 月 31 日，不拆分到月份或每日流水。

- 每条历史记录 = 一个分类 × 一个年度实际覆盖期间；提供二级分类时保存二级分类，只有大类时保存大类汇总。
- A/B/C 默认分别为大类、二级分类和年度金额，支持没有分类表头且大类纵向合并的工作表。“第一分类 / 第二分类”和“大类 / 子类”等表头均可识别；“大类、金额”两列表也可使用。请在预览前核对列和数据行范围。
- 同一二级分类的多行金额相加；同时提供大类金额和二级分类金额时，大类只作校验，必须与二级分类合计一致，避免重复入账。同一期间出现多行大类金额时提示检查分类列。
- 工作表名是 1900–2100 的年份时自动填写年份，仍可修改。2026 年覆盖截至 8 月 31 日，其他年份覆盖全年；切换工作表会重新识别列和年份。
- 二级分类在同一大类下按名称匹配，首尾空格自动清理。新名称会在预览中显示“导入时新增二级分类”，确认提交时与账单一起保存，也可手动映射到已有分类。已停用分类不会自动恢复；未知大类需要手动映射。

```csv
大类,分类,金额
日常支出,餐饮,1200.00
日常支出,超市,0
日常支出,理发,
总计,,1200.00
```

上例按年度导入后生成“日常支出 · 餐饮 1,200 元”和“日常支出 · 超市 0 元”两条记录，理发空白不生成金额。选择 2025 年时覆盖全年；选择 2026 年时仅覆盖 1–8 月，以一条累计汇总保存。

历史只覆盖所保存的分类：二级分类之间互不阻挡，大类汇总则覆盖其下所有子类。覆盖期间内不能重复记流水或做月度调整。年度未按月拆分时，月度对账需填写保留原因才能核对。早期已导入的记录保持原分类与期间。

### 月度对账

默认 A/B/C 分别为大类、子类和金额，按子类核对。单级分类表将“大类列”设为“无”，手动选择分类和金额列。

- CSV 使用 UTF-8，可带 BOM；支持双引号转义、逗号、CRLF/LF 和带引号换行。
- 点小数格式允许 `1234.56`、`1,234.56`、`¥1,234.56`；逗号小数格式需明确选择，例如 `1.234,56`。不猜测分隔符、不接受超过两位小数或任意公式文本。
- 空白不生成历史金额，明确 `0` 保存为零；对账的空白与缺失分类显示“未提供”。净支出依据允许负值，历史汇总与消费总额不接受负值。
- 总计 / 合计 / Total / Grand total 仅校验选中分类金额总和；小计不入账。带数字但不符合分类规则的行需手动排除或映射，不能静默忽略。
- XLSX 支持共享字符串、inline string、纵向合并大类及公式缓存。仅在实际合并范围内补齐大类，只读明确映射的金额列。公式不会执行；缓存缺失或错误阻止提交，缓存值可能过期，预览中会提示核实。
- 首版限制：原文件 ≤ 10 MiB；最多 10,000 行、256 列、32 张工作表；ZIP 最多 1,024 个条目，单条解压 ≤ 16 MiB、总解压 ≤ 40 MiB，单元格 ≤ 32 KiB。损坏归档、重复行/单元格、路径穿越、符号链接、XML DTD/实体声明拒绝导入。
- 不承诺 XLS、加密工作簿、任意 CSV 编码、超过上述边界的工作簿或任意复杂 Excel 功能。

## 编辑历史账单

历史文件导入 → 查看与编辑历史账单，或设置 → 导入批次与覆盖，点击有效历史记录即可修改金额、分类和起止日期。支持明确的零金额；期间不得与其他历史、每日流水或有效月度调整重叠。有退款时金额不能低于累计退款，不能变更分类，截止日须早于关联退款日期。

保存后统计重算，原、新期间内的有效对账标为待核对。原始导入来源保持不变，编辑前后快照随备份保存。已撤销记录不能编辑，修改过的批次不能直接自动撤销。

## 防重与撤销

同一原文件的同一工作表不能再次作为历史提交；同一工作簿的其他工作表（例如 2025 全年表和 2026 截至 8 月底的年度表）可以分别导入。对账文件仍按原文件摘要阻止再次提交。换名或重新导出仍进行期间、分类和金额检查。不同金额的同期间分类及任何期间重叠（包括大类与其子类之间）均作为冲突，不自动相加。

预览不是持久化结果；确认提交时再次检查最新账本。批次、历史记录 / 对账依据和来源快照同一事务保存，失败回滚。撤销保留来源和审计，停用记录而非破坏性删除。历史快照已变化、历史被对账引用、对账已修订/核对或版本已被替代时禁止自动撤销，并显示具体原因。

历史按年度实际覆盖期间保存：完整年度使用 year，2026 年 1–8 月累计使用 range；早期记录保持不变。年度汇总不均摊到各月，月度统计显示未拆分；覆盖提示不宣称所有分类连续完整。历史与已有明细重叠时需先解决原记录，本版本不提供自动用部分明细替换历史的捷径。

## 对账与调整

外部依据不参与收支统计。默认按净支出计算：外部金额 − 当前账本（消费 − 退款 + 有效调整）。消费总额口径可比较，但不能直接产生净支出调整。

同月只保留一个有效依据版本。保存新版本会停用同月旧依据及其调整，保留原金额、调整修订和核对快照。用户确认后重新核对，不叠加多个版本。

餐饮 1,200 元、外部 1,350 元，差额为 +150 元。补录真实交易可归零；无法补录时填写原因并确认 +150 元月度调整。再次计算建议调整时排除该项自身旧调整，因此不会重复增加 +150 元。后来补入真实消费后建议将旧调整修订为 0；旧修订保留，只有新修订有效。

“已核对”仅覆盖已提供分类；未解决差异或不可拆分历史必须填写保留原因。核对记录保留当时账本、调整、依据及差额。相关新增 / 编辑 / 删除 / 跨月移动或调整修订后重新标记待核对。

## 存储与依赖

保留原 `Ledger-v1.store` 路径，采用 Schema V2 新增审计实体，通过 V1→V2 轻量迁移保留现有账本。来源快照与核对记录随本地数据库保存。
